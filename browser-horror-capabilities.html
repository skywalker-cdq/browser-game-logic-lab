Browser horror games: a practical capability preflight

Horror games depend on sound, focus, and predictable rendering. A short capability preflight can explain why a feature is unavailable and offer a safe fallback before the first scare.

Probe capabilities, not performance

function browserCapabilities() {
  const canvas = document.createElement("canvas");
  return {
    webAudio: Boolean(window.AudioContext || window.webkitAudioContext),
    webgl: Boolean(canvas.getContext("webgl")),
    pointerLock: "pointerLockElement" in document,
    localStorage: canUseLocalStorage()
  };
}

function canUseLocalStorage() {
  try {
    localStorage.setItem("_probe", "1");
    localStorage.removeItem("_probe");
    return true;
  } catch {
    return false;
  }
}

Fallbacks that preserve the experience

  • Offer a mute button and visible captions when Web Audio is unavailable.
  • Use a 2D renderer or reduced effects when WebGL is missing.
  • Allow keyboard camera controls when Pointer Lock is blocked.
  • Keep a session-only mode when local storage is disabled.

Test in the right order

Run the API probe before loading a heavy scene. After startup, measure real frame time separately; API availability alone cannot promise smooth performance. Also test focus loss, a suspended audio context, and a browser refresh during a short session.
