Snake grids in the browser: capacity before coordinates

A responsive Snake board is easier to maintain when its logical grid is decided before pixel coordinates. The game can then resize without changing collision rules or food placement.

Calculate the logical board

function gridCapacity(width, height, cellSize) {
  const cell = Math.max(4, Number(cellSize));
  const columns = Math.floor(Number(width) / cell);
  const rows = Math.floor(Number(height) / cell);
  return { columns, rows, total: columns * rows };
}

function nextHead(head, direction, columns, rows, wrap = false) {
  let x = head.x + direction.x;
  let y = head.y + direction.y;
  if (wrap) {
    x = (x + columns) % columns;
    y = (y + rows) % rows;
  }
  return { x, y };
}

Rules worth keeping independent

  • Store the head, body, and food as integer {x, y} cells.
  • Multiply by cellSize only in the rendering layer.
  • Make wall collision and wrap-around a deliberate mode, not an accidental branch.
  • Keep board capacity separate from the maximum score or snake length.

Responsive test cases

Test a board whose width is not divisible by the cell size, a one-cell board, and a resize while the snake is moving. A clean design either preserves the logical board until the round ends or remaps every segment explicitly; silently rounding screen coordinates creates hard-to-reproduce collisions.
