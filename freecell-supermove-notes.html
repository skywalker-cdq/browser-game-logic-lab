FreeCell SuperMove: a small, testable capacity model

Moving a visible sequence in FreeCell is easier to reason about when the interface separates two questions: can the cards be placed in descending alternating order, and how many cards can the empty working spaces carry?

The capacity formula

For a normal SuperMove, the common upper-bound model is (freeCells + 1) * 2^workColumns. The destination column is not a working column when it is itself empty, so subtract one before calculating.

function sequenceCapacity(freeCells, emptyColumns, destinationIsEmpty) {
  const cells = Math.max(0, Number(freeCells));
  const columns = Math.max(
    0,
    Number(emptyColumns) - (destinationIsEmpty ? 1 : 0)
  );
  return (cells + 1) * 2 ** columns;
}

function canMove(sequenceLength, freeCells, emptyColumns, destinationIsEmpty) {
  return Number(sequenceLength) <= sequenceCapacity(
    freeCells, emptyColumns, destinationIsEmpty
  );
}

What the formula does not decide

  • Every adjacent pair still needs valid alternating-color rank order.
  • Foundation moves can change the number of free cells before the transfer.
  • An empty destination column is a destination, not an extra temporary column.
  • A UI should return the reason for failure instead of only disabling a button.

Boundary cases worth testing

Test zero free cells, one empty column, an empty destination, and a sequence exactly at capacity. These cases catch the most common off-by-one errors. A useful reference for the Japanese rules and examples is Solitaire JP's FreeCell movable-cards guide; it is a practical guide, not a claim that the site authored the original game.

The calculator above is intentionally dependency-free. Keep the arithmetic pure, test it separately from the DOM, and let the UI explain which working space is limiting the move.
